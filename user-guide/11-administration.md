Раздел для администратора: кто работает в системе, что кому разрешено, как
разделены контуры данных и как настроены документы, уведомления и лицензия.

---

## 11.1. Пользователи

**Меню → Администрирование → Пользователи**

![Пользователи](/user-guide/images/40-users.png)

### Создание пользователя

**«Добавить»**

![Форма пользователя](/user-guide/images/38-user-create-form.png)

| Секция | Поля |
|---|---|
| **Учётная запись** | **Логин** *, **Пароль** * |
| **ФИО** | **Фамилия** *, **Имя** *, Отчество |
| **Контакты** | Email, Телефон |
| **Доступ** | **Контрагент** *, **Роли** * |

Правила:

- **Логин** — латинские буквы, цифры, точка, дефис, подчёркивание; начинается
  с буквы; от 3 до 50 символов.
- **Роли** — минимум одна.
- **Контрагент** — организация, которую пользователь представляет.
- Телефон вводится в формате `+7 (999) 123-45-67`.

Пароль, заданный администратором, считается временным: при первом входе система
потребует заменить его (см. [Начало работы](/user-guide/01-getting-started#12-первая-смена-пароля)).

### Действия над пользователем

| Действие | Что делает |
|---|---|
| **Активировать / Деактивировать** | Деактивированный не может войти: «Ваша учётная запись ещё не активирована» |
| **Заблокировать / Разблокировать** | Блокировка закрывает вход: «Ваша учётная запись заблокирована» |
| **Изменить пароль** | Задать новый пароль пользователю |
| **Делегировать / заменить** | Передать ответственность другому человеку |
| **Удалить** | Удаление учётной записи |

### Делегирование

Инструмент на случай увольнения, отпуска или замены на объекте.

**«⋮» → «Делегировать / заменить»**:

> Вся активная ответственность пользователя «Иванов И.И.» (замечания и инспекции)
> будет переназначена на выбранного пользователя.

Выберите **«Кому передать»** и нажмите **«Делегировать»**.
Результат: «Готово: замечаний — 42, инспекций — 7».

> **Важно:** получатель должен быть заранее назначен на те же проекты, причём
> осознанно и с нужными правами. Если он не назначен, система вернёт список
> недостающих проектов и делегирование не выполнится.

## 11.2. Роли и права

**Меню → Администрирование → Роли**

![Роли](/user-guide/images/41-roles.png)

Роль — именованный набор прав. Типовой набор, поставляемый с системой:
Администратор, Системный администратор, Руководитель проекта, Главный инженер
проекта, Начальник строительного контроля, Инженер строительного контроля,
Инженер ПТО, Инженер по инженерным системам, Инженер по охране труда, Начальник
участка, Производитель работ, Представитель подрядчика, Геодезист, Специалист по
неразрушающему контролю.

### Карточка роли

![Права роли](/user-guide/images/60-role-permissions.png)

Три вкладки:

| Вкладка | Содержимое |
|---|---|
| **Основное** | **Название роли** *, Описание |
| **Пользователи** | Кто состоит в роли; **«Добавить пользователя»**, удаление из роли |
| **Права** | Матрица прав |

### Как устроены права

Право = **сущность + действие**, например «Замечание: создание».
Права сгруппированы: **Администрирование, Менеджмент, Справочники** и основной блок.

Типовые действия:

| Действие | Смысл |
|---|---|
| **Просмотр** | Базовое право; без него остальные не выдаются |
| **Создание**, **Редактирование**, **Удаление** | Операции над записями |
| **Изменение статуса** | Двигать по статусам вне персональных правил |
| **Изменение приоритета**, **Изменение ответственного** | Только для замечаний |
| **Активация/Деактивация**, **Блокировка/Разблокировка**, **Изменение пароля** | Только для пользователей |
| **Разметка на плане**, **Маркеры на плане** | Работа с планами объектов |
| **Выгрузка КС-2** | Финансовый документ, отдельное право |
| **Просмотр всех** | Системное надпроектное право: видеть записи вне назначенных проектов |

Правила, которые важно знать:

1. **«Просмотр» — фундамент.** Остальные действия зависят от него: сняв просмотр,
   вы отключите и вложенные права.
2. **Нельзя выдать право, которого нет у вас самих.** Система сообщит: «Нельзя
   управлять правом, которого нет у вас самих». Это защита от эскалации привилегий.
3. **Права роли и права пользователя складываются.** Право, полученное через роль,
   помечается «(через роль)».

### Персональные права

Права можно выдать не только роли, но и конкретному пользователю — вкладка «Права»
в карточке пользователя. Сначала сохраните запись: «Сначала сохраните пользователя,
чтобы назначать права».

> Персональные права — точечное исключение. Массовую настройку делайте ролями,
> иначе через полгода никто не сможет объяснить, почему у человека такой доступ.

## 11.3. Назначения на проекты

**Меню → Менеджмент → Назначения**

![Назначения](/user-guide/images/42-user-projects.png)

Определяет, **какие проекты видит пользователь**. Без назначения человек не увидит
ни проекта, ни его замечаний — даже имея право «Замечание: просмотр».

**«Добавить»**: выберите **Пользователя** и один или несколько **Проектов**.

Исключение — обладатели системного права **«Просмотр всех»**: они видят записи
надпроектно.

> Это первое, что нужно проверить, когда пользователь говорит «у меня пусто».

## 11.4. Роли и категории

**Меню → Менеджмент → Роли и категории**

![Роли и категории](/user-guide/images/43-role-categories.png)

Связывает **роль** с **категориями замечаний**: роль работает только со «своими»
категориями. Например, инженер по охране труда — с категорией «ОТиПБ»,
инженер по инженерным системам — с инженерными категориями.

**«Добавить»**: выберите **Роль** * и **Категории**.

## 11.5. Рабочие пространства

> Доступно только суперадминистратору (системной учётной записи).

### Пространства

**Меню → Менеджмент → Пространства**

![Пространства](/user-guide/images/44-workspaces.png)

Пространство — изолированный контур: свои проекты, замечания, справочники.
Используется, когда в одной системе работают независимые организации,
филиалы или направления.

| Поле | Описание |
|---|---|
| **Наименование** * | Название пространства |
| **Описание** | Комментарий |
| **Активно** | Неактивное недоступно для работы |
| **Пользователей** | Счётчик назначенных |

Пространство по умолчанию удалить нельзя: «Пространство по умолчанию — удаление
запрещено».

### Пользователи пространств

**Меню → Менеджмент → Пользователи пространств**

![Пользователи пространств](/user-guide/images/45-user-workspaces.png)

**«Добавить»** открывает **«Назначение пользователей»**: выберите
**Пользователей** * и **Пространства** * — назначения создаются массово.

Назначенные пространства появляются у пользователя в переключателе в шапке.

## 11.6. Настройки системы

**Меню → Настройки системы**. Требуется право **«Настройка системы: просмотр»**.

Четыре вкладки: **Общие · Провайдеры · Сессии · Лицензия**.

### Общие

![Настройки системы](/user-guide/images/46-system-settings.png)

| Блок | Назначение |
|---|---|
| **Язык системы** | Язык системных сообщений, когда у получателя ещё нет личной настройки |
| **Пользователь System** | Техническая учётная запись; пароль меняется только здесь |

### Провайдеры

![Провайдеры](/user-guide/images/54-settings-providers.png)

Каналы доставки уведомлений: Telegram, Max, Email, мобильные push.

Для каждого: **Статус** («Готов» / «Не готов»), **«Включить» / «Отключить»**,
**«Проверить»** и конфигурация в формате JSON.

Настройки Email:

- **`default_to_email`** — обязателен для проверки SMTP: на этот адрес уйдёт
  тестовое письмо.
- **«Автоматически привязывать email пользователя»** — если включено, email нового
  пользователя сразу считается подключённым каналом; если выключено, пользователь
  подтверждает адрес кодом.
- **«Шаблон письма»** — фирменный HTML-макет, в который оборачиваются все
  email-уведомления. Тело сообщения подставляется в `{{Body}}`, название системы —
  в `{{AppName}}`, адрес системы — в `{{AppUrl}}`. Есть предпросмотр, вставка
  макета по умолчанию и загрузка баннера (встраивается в письмо, до 1 МБ;
  рекомендуется до 400 КБ).

> Макет применяется только к email. В мессенджерах и уведомлениях внутри системы
> оформление не используется.

### Сессии

![Сессии](/user-guide/images/55-settings-sessions.png)

Список живых сессий: **Пользователь, IP, Клиент, Вход, Неактивен с, Жёсткий выход**.

Кнопка **«Завершить»** разлогинивает пользователя и **сразу освобождает
лицензионное место**. Подтверждение: «Завершить сессию пользователя «...»?
Он будет разлогинен, место освободится».

### Лицензия

![Лицензия](/user-guide/images/56-settings-license.png)

| Показатель | Значение |
|---|---|
| **Статус** | «Действительна» / «Недействительна» с причиной |
| **Клиент**, **Продукт** | Кому и на что выдана |
| **Мест по лицензии** | Лимит одновременных пользователей |
| **Активных сейчас**, **Живых сессий** | Текущее потребление |
| **Пользователей (вкл. / всего)** | Включённые и все учётные записи |
| **Выдана**, **Действует до** | Срок действия |
| **Модули в лицензии** | Инспекции, Предписания, Учёт выполненных работ |

Причины недействительности: лицензия не найдена, срок истёк, срок ещё не начался,
лицензия для другого продукта, привязана к другому серверу.

**Загрузка лицензии:** перетащите файл `.lic` в область и нажмите **«Загрузить»**.
Применяется сразу, без перезапуска.

> Модуль, не входящий в лицензию, не исчезает: его экраны открываются на чтение
> с панелью «Этот раздел не входит в вашу лицензию. Данные доступны только для
> просмотра».

## 11.7. Настройки шаблонов документов

**Меню → Настройки шаблонов**. Право **«Шаблоны документов»**.

![Настройки шаблонов](/user-guide/images/47-document-templates.png)

Две вкладки: **Предписания** и **Инспекции**. Устроены одинаково.

![Шаблоны отчётов инспекций](/user-guide/images/57-templates-inspections.png)

### Версии шаблона

Таблица: **Версия, Активен, Создано, Автор, Файл**.

- **«Добавить»** создаёт новую версию.
- **«Сделать активной»** назначает версию, по которой формируются документы.
- Неактивная версия открыта только на чтение: «Для редактирования создайте новую
  версию шаблона через кнопку "Добавить"».

Для предписаний доступен выбор **контрагента**: можно сделать персональный шаблон
для конкретного подрядчика, иначе используется **«Общий шаблон»**.

### Загрузка DOCX

Перетащите DOCX в область **«Текущий шаблон»** или нажмите для выбора.
Блок **«Проверка шаблона»** покажет: **Найдено параметров**, **Ошибок**,
статус «Готов» / «Есть ошибки» / «Есть предупреждения».

Кнопка **«Пример»** скачивает образец шаблона — с него удобно начинать.

### Разметка DOCX

Параметры вставляются в Word двумя способами:

1. **Content Control Tag** — тег элемента управления содержимым;
2. **текстовый маркер** в двойных фигурных скобках.

Примеры общих параметров: `Prescription.Number`, `Inspection.Number`,
`ProjectObject.Title`.

**Табличная часть замечаний** настраивается отдельно: сделайте в таблице одну
строку-образец для одного замечания и разместите в ней параметры замечания —
`Issue.Id`, `Issue.Description`, `Issue.Status`. При генерации строка повторится
для каждого замечания.

> Параметр `Issue.Images` лучше вставлять отдельным абзацем или через Content
> Control Tag: внутри обычного текста фотографии могут замениться текстовой пометкой.

### Настройка параметров

Таблица **Параметр · Наименование · Источник**:

- **«Добавить общий параметр»** / **«Добавить параметр строки»** — вручную;
- **«Загрузить параметры из шаблона»** — вытащить теги прямо из DOCX;
- **Источник** — системное значение (Предписание, Замечание, Проект, Объект,
  Контрагент, Ответственный, Автор, Договор и т. д.), изображения или
  **пользовательское поле**.

**«Проверить»** сверяет DOCX и таблицу параметров и сообщает о расхождениях:

| Сообщение | Смысл |
|---|---|
| «Есть параметр без имени» | Пустая строка в таблице |
| «Для параметра "X" не выбран источник» | Не задано, откуда брать значение |
| «Параметр "X" настроен в таблице, но отсутствует в DOCX-шаблоне» | Лишняя строка |
| «Параметр "X" найден в DOCX-шаблоне, но отсутствует в таблице» | Тег есть, значение подставить неоткуда |
| «Параметр "X" добавлен несколько раз» | Дубликат |

Итог: «Шаблон заполнен корректно» либо «Проверка нашла ошибки».

## 11.8. Аудит

История изменений доступна прямо в карточках — вкладка **«Активность»**:
кто, когда и что поменял, в формате «Изменено «Статус»: с «В работе» на «Выполнено»».
Записи создаются автоматически и не редактируются.
