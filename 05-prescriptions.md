## 5.1. Как создаётся предписание

Предписание не заводится «с нуля» — оно **формируется по замечаниям**.

**Вариант 1 — по одному замечанию.**
В списке замечаний: **«⋮» → «Сформировать предписание»**.
Подтвердите: «Сформировать предписание по этому замечанию?».

**Вариант 2 — по нескольким сразу.**
Отметьте замечания флажками → **«Действия» → «Сформировать предписание»**.
Подтвердите: «Сформировать предписание по выбранным замечаниям (7)?».

Система подставит данные в активный DOCX-шаблон, создаст запись предписания и
сообщит **«Предписание сформировано»**.

Если замечания не выбраны, появится предупреждение «Выберите замечания для
формирования предписания».

> Шаблон может быть свой для каждого контрагента; если персонального нет,
> берётся общий. Настройка — [Администрирование](/user-guide/11-administration).

## 5.2. Реестр предписаний

**Меню → Предписания**

![Реестр предписаний](/user-guide/images/14-prescriptions.png)

Колонки: **№, Проект, Объект, Контрагент, Статус, Замечаний, Создано, Автор, Документ**.

Действия по строке («⋮»):

| Пункт | Действие |
|---|---|
| **Просмотр** | Открыть карточку |
| **Скачать документ** | Выгрузить сформированный DOCX |
| **Сменить статус** | Допустимые переходы |
| **Удалить** | С подтверждением «Удалить предписание №12?» |

Если файл не сформировался, при скачивании появится «Документ предписания не найден».

## 5.3. Карточка предписания

![Карточка предписания](/user-guide/images/15-prescription-card.png)

**Шапка:** Проект, Объект, Контрагент, Статус, Создано, Автор, количество замечаний,
ссылка на документ. Значок загрузки справа сверху скачивает DOCX, «⋮» — действия.

**Вкладки:**

- **Замечания** — состав предписания: № замечания, Статус, Приоритет, Проект, Объект,
  Контрагент, Категория, Тип, Ответственный, Плановая дата, Описание. Каждая строка
  открывается в карточку замечания.
- **Вложения** — файлы предписания.
- **Активность** — история изменений.

> Замечания живут своей жизнью: включение в предписание не меняет их статусы.
> Предписание фиксирует **факт выдачи требования**, а устранение отслеживается
> по самим замечаниям.

## 5.4. Жизненный цикл предписания

```
Новый ──────► В работе ──────► Закрыто
                  │
                  └─────────► Отклонено
```

| Из статуса | Куда можно |
|---|---|
| **Новый** | В работе |
| **В работе** | Закрыто, Отклонено |
| **Закрыто** | — конечный |
| **Отклонено** | — конечный |

Двигать предписание по статусам может **ответственный** либо обладатель права
«Предписание: изменение статуса». Часть предписаний закрыта для смены статуса на
уровне записи — тогда пункт погашен с пояснением «Недостаточно прав для смены
статуса этой записи».

## 5.5. Права на предписания

| Право | Что открывает |
|---|---|
| **Просмотр** | Видеть реестр и карточки |
| **Создание** | Формировать предписания по замечаниям |
| **Редактирование** | Менять реквизиты |
| **Удаление** | Удалять |
| **Изменение статуса** | Двигать по статусам |
