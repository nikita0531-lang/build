## 13.1. Запустить новый проект с нуля

**Кто:** администратор + руководитель проекта.

1. **Завести справочники** (если система новая):
   **Справочники → Справочники замечаний** — категории и типы.
   У типов заполните **«Ориентировочное время»**, чтобы сроки считались сами.
   **Справочники → Контрагенты** — подрядчики.
   **Справочники → Виды работ**, **Единицы измерения**.
2. **Создать проект**: **Проекты → «Добавить»** — название, описание, изображение.
   При необходимости включите «Требовать тип замечания при создании».
3. **Построить дерево объектов**: карточка проекта → **«Объекты»**.
   Вручную сверху вниз (корпуса → секции → этажи → помещения) либо одним файлом
   через **«Импорт»**.
4. **Загрузить планы**: карточка объекта → **«План»** → «Выбрать» или
   «Загрузить и обрезать». Разметьте зоны дочерних объектов.
5. **Завести пользователей**: **Администрирование → Пользователи → «Добавить»**,
   указать контрагента и роли.
6. **Дать доступ к проекту**: **Менеджмент → Назначения** — привязать пользователей
   к проекту. Без этого шага люди не увидят проект.
7. **Перевести проект в работу**: «⋮» → «Сменить статус» → «В работе».

## 13.2. Зафиксировать замечание на объекте

**Кто:** инспектор, технадзор, прораб. **Права:** «Замечание: создание».

**С телефона (рекомендуется на площадке):**

1. **Замечания → создать**.
2. Проект → Объект → Категория → Тип → Приоритет.
3. Сфотографируйте нарушение.
4. Укажите ответственного и плановую дату (подставится автоматически по типу).
5. Опишите, что нужно исправить, и сохраните.

**Из веб-интерфейса:**

1. **Проекты → проект → «Замечания» → «Добавить»**.
2. Заполните форму, приложите файлы в карточке после создания.

**Если нарушений несколько и они однотипные** — нажмите **«Добавить описание»**
и введите каждое отдельной строкой: система создаст отдельное замечание на каждое
описание с общими проектом, объектом, типом, сроком и ответственным.

## 13.3. Провести цикл устранения замечания

**Кто:** исполнитель и автор замечания.

| Шаг | Кто | Действие |
|---|---|---|
| 1 | Исполнитель | Получает уведомление, открывает замечание, ставит **«В работе»** |
| 2 | Исполнитель | Устраняет, прикладывает фото результата, пишет в чат |
| 3 | Исполнитель | Ставит **«Выполнено»** |
| 4 | Автор | Проверяет и ставит **«На проверке»** |
| 5 | Автор | **«Закрыто»**, если всё в порядке, или **«На доработку»**, если нет |
| 6 | Исполнитель | Из «На доработку» возвращает в **«В работе»** и повторяет цикл |

Помните: шаги 4 и 5 доступны **только автору** замечания (или обладателю права
«Изменение статуса»).

## 13.4. Провести инспекцию по чек-листу

**Кто:** инженер строительного контроля. **Права:** «Инспекция: создание»,
назначение инспектором.

**Подготовка (один раз):**
**Справочники → Шаблоны чек-листов → «Добавить»** — блоки и пункты, типы ответов,
допуски, признак обязательности.

**Планирование:**

1. **Инспекции → «Добавить»**.
2. Проект и объект.
3. Категория + вид работ → выберите **шаблон чек-листа**.
4. Ответственный подрядчик, инспектор, ответственный.
5. Через значок календаря проверьте **загрузку инспектора** и назначьте время на
   свободный слот.
6. Сохраните — инспекция получит статус «Не начата», инспектор получит уведомление.

**Проведение (на объекте, с телефона или в вебе):**

1. Откройте инспекцию, нажмите **«В работу»**.
2. Идите по чек-листу: отвечайте на пункты, сверяясь с **«Допуском»**.
3. К пункту прикладывайте фото — кнопка **«Вложения»**.
4. Если пункт провален — **«+ Замечания»**: замечание создастся со ссылкой
   на инспекцию и пункт.
5. Нажмите **«Завершить»** и укажите **Результат**:
   «Пройдена», «Пройдена с замечаниями» или «Не пройдена».

**После:**
**«⋮» → «Скачать результат»** — отчёт в Word по активному шаблону.

## 13.5. Выписать предписание подрядчику

**Кто:** руководитель проекта, строительный контроль.
**Права:** «Предписание: создание».

**Подготовка (один раз):**
**Настройки шаблонов → «Предписания»** — загрузите DOCX-шаблон, настройте
параметры, нажмите **«Проверить»**, сделайте версию активной. При необходимости
сделайте отдельный шаблон под конкретного контрагента.

**Выпуск:**

1. **Активные замечания** — отфильтруйте по контрагенту, объекту, статусу.
2. Отметьте нужные замечания флажками.
3. **«Действия» → «Сформировать предписание»**, подтвердите.
4. **Предписания** → открыть карточку → скачать DOCX и отправить подрядчику.
5. Двигайте предписание по статусам: «Новый» → «В работе» → «Закрыто».

Устранение отслеживайте по самим замечаниям — их статусы предписание не меняет.

## 13.6. Учесть и принять выполненные работы

**Кто:** производитель работ + строительный контроль.

1. **Договоры → «Добавить»** — номер, контрагент, сроки, проект.
2. **Работы → «Добавить»** — работа по договору: объём, единица, цена, сроки,
   ответственный. Для составных работ выберите тип **«Комплексная»** и заведите
   подработы.
3. **Внесение факта:** карточка работы → **«Внести выполнение»** — дата и объём.
   Статус работы автоматически станет «В работе».
4. **На приёмку:** **«Запросить инспекцию»** — отметьте записи журнала.
   Они перейдут в «Готов к приёмке».
5. **Проверка:** инспектор проводит инспекцию и завершает её с результатом.
   «Пройдена» / «Пройдена с замечаниями» → объём **«Принят»**,
   «Не пройдена» → **«Отклонён»**.
6. **Подписание:** записи в статусе «Принят» переводятся в **«Подписано»**
   (право «Журнал выполнения: изменение статуса»).
7. **Выгрузка:** **Работы** → **«Выгрузка КС-2»** в панели инструментов.

Отклонённый объём после переделки возвращается в «В работе» и снова отдаётся
на приёмку.

## 13.7. Подключить нового сотрудника

**Кто:** администратор.

1. **Администрирование → Пользователи → «Добавить»**: логин, временный пароль,
   ФИО, контакты, **контрагент**, **роли**.
2. **Менеджмент → Назначения**: привязать к проектам.
3. При необходимости — **Менеджмент → Пользователи пространств**.
4. Передать логин и временный пароль. При первом входе система потребует
   сменить пароль.
5. Сотрудник настраивает каналы уведомлений: **Профиль → «Мессенджеры и каналы»**
   и **«Матрица уведомлений»**.

**Проверка «почему пусто»** — по порядку:
назначен ли на проект → есть ли право просмотра у роли → то ли выбрано
пространство → активна ли учётная запись.

## 13.8. Передать дела при увольнении или отпуске

**Кто:** администратор. 

1. Убедитесь, что **получатель уже назначен на те же проекты** с нужными правами.
2. **Администрирование → Пользователи → «⋮» → «Делегировать / заменить»**.
3. Выберите **«Кому передать»** → **«Делегировать»**.
4. Проверьте результат: «Готово: замечаний — 42, инспекций — 7».
5. Заблокируйте или деактивируйте учётную запись уходящего.
6. При необходимости завершите его сессии:
   **Настройки системы → Сессии → «Завершить»** — освободится лицензионное место.

Если получатель не назначен на нужные проекты, система вернёт список недостающих
и делегирование не выполнится — сначала выдайте доступ.

## 13.9. Собрать отчёт для совещания

**Кто:** руководитель.

1. **Аналитика → «Замечания»**: выберите проекты, контрагентов и период.
   «Замечания по статусам» — сколько открыто; «Динамика по времени» — растёт ли
   очередь; «Замечания по контрагентам и статусам» — кто копит.
2. **Карточка проекта → «Шахматка»** — где физически скопились замечания.
3. **Аналитика → «Работы»** — S-кривая план/факт и прогноз завершения.
4. **Активные замечания** → фильтр «просроченные» по плановой дате →
   **XLSX** — выгрузится весь набор по фильтрам, а не только страница.

## 13.10. Настроить уведомления, чтобы их читали

**Кто:** администратор + каждый пользователь.

**Администратор:**
**Настройки системы → Провайдеры** — включить нужные каналы, проверить их кнопкой
**«Проверить»**. Для Email обязательно задать `default_to_email` и оформить
HTML-макет письма.

**Пользователь:**
**Профиль → «Мессенджеры и каналы»** — подключить Telegram / Max / Email.
**«Матрица уведомлений»** — оставить «В системе» везде, а во внешние каналы вывести
только требующее немедленной реакции: новые назначения, просрочки, смену статуса.
Нажать **«Сохранить»**.
